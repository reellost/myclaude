# 微信小游戏 MVP 排期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 6 周内完成“女主播逆袭到 MCN 起步”的微信小游戏 MVP，可用于内部试玩、小规模验证题材与广告变现。

**Architecture:** 排期按“先跑通个人成长闭环，再接入 MCN 扩张闭环，最后补广告、分享、内容和测试”推进。优先级严格围绕 P0 功能，所有美术、剧情、页面和数值都服务于首版验证，不扩展复杂支线。

**Tech Stack:** 微信小游戏客户端（建议 Cocos Creator 3.x）、配置表驱动数值、微信广告与分享能力、2D UI/角色动画资源

---

## 排期假设

1. 默认团队规模为 4 人小团队。
2. 角色配置建议为：1 名策划/制作人、2 名客户端/玩法程序、1 名 UI/2D 美术。
3. QA、运营、文案由策划兼任，或在第 5-6 周临时补位。
4. 首版只做需求文档中定义的 P0 和最小内容量，不扩展 PvP、复杂换装、复杂剧情分支。
5. 如果实际只有 3 人团队，整体排期建议从 6 周顺延到 8 周。

## 里程碑定义

- M1：跑通“女主成长 -> 开播产流 -> 带货赚钱 -> 升级自己/房间”的前期闭环。
- M2：跑通“解锁招募 -> 签约主播 -> 公司升级 -> 多直播间扩张”的后期闭环。
- M3：完成广告、分享、任务、章节内容、调优和提审前测试。

## 周排期总览

| 周次 | 目标 | 核心产出 |
| --- | --- | --- |
| 第 1 周 | 冻结范围与搭原型 | 页面流程、核心数值骨架、主循环原型 |
| 第 2 周 | 完成前期个人成长闭环 | 女主成长、直播间成长、开播产流、首轮带货 |
| 第 3 周 | 完成后期公司扩张闭环 | 招募主播、公司升级、多直播位、章节推进 |
| 第 4 周 | 接入商业化与基础运营能力 | 广告、离线收益、任务、分享助力 |
| 第 5 周 | 内容填充与体验打磨 | 5 章内容、主播池、商品池、演出与 UI polish |
| 第 6 周 | 联调、QA、提审准备 | 性能优化、埋点、回归测试、提审包 |

### Task 1: 第 1 周 - 范围冻结与核心原型

**目标：** 把首版范围、页面结构和核心数值关系一次性定死，避免后面反复改方向。

**责任人：** 策划主导，程序和美术同步参与

- [ ] 确认 P0 功能清单，冻结不做项。
- [ ] 画出最小页面流程图：开场剧情页、主直播间主页、主角成长页、直播间升级页、商品带货页、招募主播页、公司成长页、任务页。
- [ ] 输出核心数值关系草表：主角成长、直播间成长、流量、金币、公司等级、商品收益。
- [ ] 确认章节结构：至少 5 章，从“被辞退后的出租屋重启”到“本地热门 MCN 机构”。
- [ ] 做可点击低保真原型或静态线框，确认主界面信息层级不复杂。
- [ ] 输出美术风格方向板，锁定女主形象、直播间初始风格、整体 UI 气质。

**验收标准：**

1. 团队对首版做什么和不做什么没有歧义。
2. 所有人能用一张图说明游戏从开局到第 3 章的流程。
3. 数值表已经明确基础资源和升级关系，不再临时加货币。

### Task 2: 第 2 周 - 前期个人成长闭环开发

**目标：** 跑通女主从重新开播到获得第一波稳定收益的核心体验。

**责任人：** 程序主导，策划配表，美术出首批资产

- [ ] 实现开场剧情与新手引导基础流程。
- [ ] 实现主角成长系统的 3 个首版入口：化妆、技能、穿搭。
- [ ] 实现直播间成长系统的首版入口：设备升级和房间阶段变化。
- [ ] 实现自动开播与自动产流逻辑。
- [ ] 实现首个带货商品位和自动收益结算。
- [ ] 接入第一轮新手引导，确保 60 秒内完成第一次完整闭环。
- [ ] 用占位资源把女主形象变化和房间变化表现出来。

**验收标准：**

1. 玩家可以从开场一路走到第一次收益和第一次升级。
2. 女主成长和房间成长都能直接影响流量或收益。
3. 新手阶段没有复杂分支，主路径清晰。

### Task 3: 第 3 周 - MCN 扩张闭环开发

**目标：** 跑通从个人直播到招募主播、扩公司、进入 MCN 阶段的第二闭环。

**责任人：** 程序主导，策划补中后期配置

- [ ] 实现招募主播系统，包括招募、上阵、升级。
- [ ] 实现公司等级系统与招募解锁条件。
- [ ] 实现多直播位或多直播间的基础承载逻辑。
- [ ] 实现章节推进系统，至少支撑前 3 章完整推进。
- [ ] 打通“主角成长 -> 解锁招募 -> 公司升级 -> 多主播产流”的完整关系。
- [ ] 补首批 3-4 名主播的差异化配置和立绘占位。

**验收标准：**

1. 玩家可以自然从“我一个人播”过渡到“我开始签别人”。
2. 公司升级不只是数字变化，而是有实际解锁内容。
3. 主循环已经同时覆盖前期逆袭和后期扩张两段体验。

### Task 4: 第 4 周 - 广告、任务与分享接入

**目标：** 让小游戏具备基础商业化能力和微信生态传播能力。

**责任人：** 程序与策划协同，运营辅助测试

- [ ] 接入激励广告点位：离线双倍、升级加速、免费招募、爆单翻倍。
- [ ] 接入基础插屏广告策略，控制在低打扰节点出现。
- [ ] 实现离线收益系统。
- [ ] 实现章节任务和基础日常任务系统。
- [ ] 实现分享助力和成长海报基础能力。
- [ ] 对广告收益做首轮数值校准，确保“看广告值得，但不看也能玩”。

**验收标准：**

1. 广告点位已经接进完整玩法闭环，而不是后贴的按钮。
2. 离线收益、任务、分享都能对回流和留存形成正向帮助。
3. 第 1-3 章体验中至少有 3 个广告点位是自然且合理的。

### Task 5: 第 5 周 - 内容填充与体验打磨

**目标：** 从“能跑”升级到“像一个能测的游戏”。

**责任人：** 策划和美术主导，程序修体验问题

- [ ] 补齐 5 个章节目标与章节奖励。
- [ ] 补齐 6-10 名可招募主播的基础内容量。
- [ ] 补齐 3 类商品赛道和对应收益节奏。
- [ ] 完善女主妆容变化、房间阶段变化、升级演出和关键弹窗。
- [ ] 做 UI 第一轮 polish，减少拥挤感和信息负担。
- [ ] 做体验向调优：新手节奏、收益速度、广告频率、章节推进节奏。

**验收标准：**

1. 玩家从开局到第 5 章都能持续获得新鲜反馈。
2. UI 和演出已经具备基础完成度，不再像纯后台原型。
3. 玩法节奏符合“1-3 分钟一轮有效成长”的目标。

### Task 6: 第 6 周 - 联调、QA 与提审准备

**目标：** 把 MVP 做到可提审、可测试、可对外验证。

**责任人：** 全员参与，策划/制作人统筹

- [ ] 做全流程回归测试，重点覆盖新手引导、广告、离线收益、章节推进、分享链路。
- [ ] 修复阻断体验的高优先级 Bug。
- [ ] 做性能检查，确保主界面、关键弹窗和广告回切稳定。
- [ ] 补基础埋点：新手完成率、广告触发率、章节到达率、分享使用率。
- [ ] 准备提审素材、版本说明和测试账号。
- [ ] 留出至少 2-3 天缓冲给修 Bug 和 SDK 问题。

**验收标准：**

1. 没有阻断主循环的高优先级问题。
2. 广告与分享链路稳定可用。
3. 已具备内部试玩和小规模验证条件。

## 角色排期建议

### 策划/制作人

1. 第 1 周重点做范围、流程、数值骨架。
2. 第 2-4 周重点做配置、章节、任务、广告收益规则。
3. 第 5-6 周重点做体验调优、测试排期、问题跟进。

### 程序

1. 第 1 周先搭主循环骨架和页面框架。
2. 第 2-3 周优先做成长、收益、章节和招募逻辑。
3. 第 4 周集中处理广告、分享、离线收益。
4. 第 5-6 周做稳定性、性能、埋点和 Bug 修复。

### 美术/UI

1. 第 1 周锁风格和核心 UI 规范。
2. 第 2-3 周优先支持女主、房间、主播、关键界面。
3. 第 4-5 周完善升级演出、弹窗、分享图和章节包装。
4. 第 6 周配合修正视觉问题和提审素材。

## 风险缓冲建议

1. 故事演出一定要短，不然会拖慢开发和新手节奏。
2. 如果第 2 周结束时前期闭环还没跑通，必须立刻砍掉非必要装扮表现。
3. 如果第 3 周结束时后期 MCN 闭环还没跑通，优先保留“招募 + 公司等级 + 多直播位”，砍复杂主播差异。
4. 如果第 4 周广告接入不稳定，第 5 周必须优先解决 SDK 和回切问题，内容填充后置。
5. 第 6 周不要新增功能，只修问题和准备提审。

## 最终交付物清单

1. 一版可在微信小游戏环境中运行的 MVP 包。
2. 5 章可推进的基础内容。
3. 6-10 名可招募主播。
4. 主角成长、直播间成长、招募扩张、带货收益四条核心链路。
5. 激励广告、离线收益、基础分享助力。
6. 基础埋点和验证数据口径。

## 建议决策

如果你希望尽快验证题材和广告模型，这版排期建议就按 6 周执行；如果团队少于 4 人，建议不要压缩功能，而是把周期顺延到 8 周。
