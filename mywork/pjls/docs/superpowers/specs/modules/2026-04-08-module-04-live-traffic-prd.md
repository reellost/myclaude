# 模块 04：开播产流系统 PRD

## 1. 模块定位

开播产流系统是首版最核心的自动化玩法系统，负责把“角色养成”和“经营增长”转化为可持续上涨的流量资源。

## 2. 设计目标

1. 做到零复杂操作，玩家一看就懂。
2. 让流量增长足够直观，支撑放置爽感。
3. 为带货收益和广告加速提供稳定基础。

## 3. 玩家体验目标

玩家应该感受到：

1. 她开始播了，观众真的在涨。
2. 我升级以后，涨得更快了。
3. 我不用复杂操作，也能持续有事发生。

## 4. 功能范围

MVP 包含：

1. 开播状态切换
2. 自动产流逻辑
3. 实时流量显示
4. 流量增长反馈表现
5. 多主播加入后的总流量汇总

MVP 不包含：

1. 节奏点击玩法
2. 实时评论互动玩法
3. 玩家手动操作表演玩法

## 5. 核心规则

### 5.1 基础状态

建议至少有三种状态：

1. 未开播
2. 开播中
3. 加速中

### 5.2 产流逻辑

流量由以下因素共同决定：

1. 主角基础流量
2. 已上阵主播总流量
3. 直播间加成
4. 公司加成
5. 临时 Buff

推荐公式方向：

`总流量/秒 = (主角流量 + 主播总流量) x 直播间系数 x 公司系数 x Buff 系数`

### 5.3 表现反馈

建议同时用三层反馈表现产流：

1. 主界面数值持续上涨
2. 角色和房间的直播演出持续播放
3. 关键节点出现“人气上涨”“直播间热度提升”等轻提示

## 6. 页面与交互

主界面必须能同时展示：

1. 当前是否在开播
2. 当前流量增速
3. 当前总流量池
4. 可触发的加速入口

交互要求：

1. 开播按钮必须醒目
2. 一旦进入自动直播，应减少玩家反复确认成本
3. 主界面以“看增长”为主，而不是反复切页面

## 7. 配置建议

首版建议配置：

1. 女主默认长期上阵，不可下阵
2. 招募主播后可增加总流量产出
3. 流量演出节奏前快后稳，避免前期显得太慢

## 8. 与其他模块的关系

1. 上游输入来自模块 02、03、06、07
2. 下游输出给模块 05
3. 广告模块 09 中的加速效果应直接作用于本模块

## 9. MVP 边界

首版只做“自动开播 + 自动产流 + 可感知反馈”，不做复杂直播玩法。

## 10. 验收标准

1. 玩家在开播后能立刻理解“流量正在增长”。
2. 升级主角、房间、主播后，产流速度变化足够明显。
3. 主界面主要反馈集中在增长，不会信息过载。
4. 模块可以稳定支撑后续带货与广告系统。
