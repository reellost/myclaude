# 微信小游戏页面流程与广告弹窗顺序图 V1

## 1. 文档用途

本文件用于把广告点位从“页面上有哪些点”进一步推进到“玩家实际游玩时会按什么顺序看到哪些弹窗”。

它主要解决三个落地问题：

1. 同一条流程里多个弹窗谁先谁后。
2. 哪些弹窗是阻塞式，哪些只能弱提示。
3. 什么场景下必须压制广告，保证体验不断流。

本文件默认承接以下已有结论：

1. 离线收益系数已调整到 `0.25`
2. 短会话里不叠两种强广告
3. 首版广告主打 5 个激励点位，插屏从严控制

## 2. 页面与弹窗分层

### 2.1 页面层

首版核心页面如下：

1. `boot_story_page`：开场剧情页
2. `main_live_page`：主直播主界面
3. `hero_growth_page`：主角成长页
4. `room_growth_page`：直播间成长页
5. `company_page`：公司升级页
6. `recruit_page`：主播招募页
7. `task_page`：任务页

### 2.2 弹窗层

首版核心弹窗如下：

1. `offline_reward_popup`：离线收益结算
2. `chapter_reward_popup`：章节奖励结算
3. `chapter_reward_double_popup`：章节奖励翻倍确认
4. `ad_reward_result_popup`：广告奖励结果确认
5. `free_recruit_popup`：免费招募确认
6. `system_unlock_popup`：新功能解锁提示
7. `interstitial_ad`：插屏广告

### 2.3 弹窗优先级

为了避免相互打断，首版建议固定优先级如下：

1. `新手强制引导`
2. `离线收益结算`
3. `章节奖励结算`
4. `系统解锁提示`
5. `激励广告确认`
6. `广告奖励结果`
7. `插屏广告`

同一时刻只允许出现一个阻塞式弹窗。高优先级未处理完，低优先级必须排队。

## 3. 流程总原则

1. 强情绪节点先给奖励，再考虑广告。
2. 激励广告永远放在“领奖前选择”或“卡点时建议”，不要放在高反馈后硬插。
3. 插屏广告只允许在“已经完成一个完整动作”之后出现。
4. 新手前 60 秒内不允许出现插屏广告。
5. 任意激励广告结束后 `90 秒` 内不允许出现插屏广告。

## 4. 五条核心流程

### 4.1 流程 A：首登新手流程

适用场景：首次进入游戏，尚未完成第一轮教学。

推荐顺序：

1. `boot_story_page`
2. `新手剧情引导`
3. `main_live_page`
4. `主角成长引导`
5. `房间成长引导`
6. `首次开播`
7. `首次商品选择`
8. `首次收益反馈`
9. `首次升级反馈`
10. `弱提示章节奖励翻倍或双倍收益价值`

这个流程里不能出现：

1. 插屏广告
2. 离线收益弹窗
3. 爆单广告强提醒

Mermaid 流程图：

```mermaid
flowchart LR
  A["开场剧情"] --> B["主界面落地"]
  B --> C["主角成长引导"]
  C --> D["房间成长引导"]
  D --> E["首次开播"]
  E --> F["首次商品选择"]
  F --> G["首次收益反馈"]
  G --> H["首次升级反馈"]
  H --> I["弱提示广告价值"]
```

### 4.2 流程 B：普通回流上线流程

适用场景：玩家完成新手后再次登录。

推荐顺序：

1. 进入 `main_live_page`
2. 弹出 `offline_reward_popup`
3. 玩家选择普通领取或离线双倍
4. 若看广告，则进入 `ad_reward_result_popup`
5. 若本次登录有新功能解锁，再弹 `system_unlock_popup`
6. 回到主界面自由操作
7. `90 秒` 内不出插屏

Mermaid 流程图：

```mermaid
flowchart LR
  A["回流进入主界面"] --> B["离线收益弹窗"]
  B -->|"普通领取"| C["功能解锁提示（如有）"]
  B -->|"双倍领取"| D["广告结果确认"]
  D --> C
  C --> E["回到主界面自由操作"]
```

### 4.3 流程 C：章节中段短会话流程

适用场景：玩家在一段 `3-6 分钟` 的正常推进会话中卡在成长中段。

推荐顺序：

1. `main_live_page`
2. 进行一轮自然经营
3. 触发成长小卡点
4. 若当前会话强广告主轴是“加速”，弹 `开播加速建议`
5. 若当前会话强广告主轴是“爆单”，弹 `爆单建议`
6. 广告完成后回主界面继续推进
7. 本段会话内不再强推另一种强广告

这个流程的重点不是多弹，而是只弹对当前卡点最有帮助的那个。

### 4.4 流程 D：章节完成流程

适用场景：玩家达成章节主目标。

推荐顺序：

1. `章节完成演出`
2. `chapter_reward_popup`
3. 在同一弹窗内展示 `章节奖励翻倍` 选择
4. 领取奖励
5. 如有新系统解锁，弹 `system_unlock_popup`
6. 若满足章节插屏条件，等待至少一个确认动作后再出 `interstitial_ad`
7. 回到主界面

Mermaid 流程图：

```mermaid
flowchart LR
  A["章节完成演出"] --> B["章节奖励弹窗"]
  B --> C["奖励翻倍选择"]
  C --> D["奖励到账"]
  D --> E["新系统解锁提示（如有）"]
  E --> F["章节插屏（可选）"]
  F --> G["回到主界面"]
```

### 4.5 流程 E：首次招募流程

适用场景：第 3 章首次解锁主播招募。

推荐顺序：

1. `system_unlock_popup` 提示“主播招募已开启”
2. 玩家进入 `recruit_page`
3. 展示招募池和免费招募入口
4. 若当日广告次数可用，优先展示 `free_recruit_popup`
5. 招募完成后先播结果演出
6. 回到 `main_live_page` 或直播位上阵页
7. 招募结果后的 `15 秒` 内禁止插屏

这个流程里，免费招募广告优先级高于爆单广告，因为它承接的是新内容解锁，而不是数值卡点。

## 5. 场景级弹窗顺序表

### 5.1 登录回流

固定顺序：

1. `offline_reward_popup`
2. `ad_reward_result_popup`（仅在看双倍时）
3. `system_unlock_popup`（如有）
4. `main_live_page`

### 5.2 章节完成

固定顺序：

1. `chapter_reward_popup`
2. `chapter_reward_double_popup`
3. `system_unlock_popup`
4. `interstitial_ad`（可选）

### 5.3 首次招募

固定顺序：

1. `system_unlock_popup`
2. `free_recruit_popup`
3. `招募结果演出`
4. `上阵引导`

## 6. 不允许的顺序

首版明确禁止以下弹窗顺序：

1. `离线双倍 -> 章节插屏` 直接连发
2. `章节奖励翻倍 -> 章节插屏` 无确认间隔连发
3. `开播加速 -> 爆单翻倍` 在同一段 180 秒内连续强推
4. `免费招募 -> 插屏广告` 在招募结果出现后 15 秒内触发
5. `章节完成演出 -> 插屏广告 -> 章节奖励` 倒置顺序

## 7. 阻塞与非阻塞定义

### 7.1 阻塞式

必须处理后才能继续主流程：

1. `offline_reward_popup`
2. `chapter_reward_popup`
3. `chapter_reward_double_popup`
4. `free_recruit_popup`
5. `system_unlock_popup`

### 7.2 非阻塞式

只做角标、弱提示或按钮发光：

1. `开播加速建议`
2. `爆单建议`
3. `任务可领取红点`
4. `返回主界面插屏候选状态`

## 8. 新手前 10 分钟广告顺序建议

建议按以下节奏控制：

1. `0-2 分钟`：不出插屏，只允许剧情和弱提示
2. `2-4 分钟`：可以出现一次 `章节奖励翻倍` 或第一次弱广告提示
3. `4-8 分钟`：开始允许 `开播加速`
4. `8-10 分钟`：如果进入第 2 章中段，可首次出现 `爆单翻倍`

## 9. 客户端实现建议

如果客户端要做统一弹窗调度，建议至少有三层控制：

1. `event_queue`：记录当前待弹事件
2. `popup_priority`：按优先级出队
3. `suppression_rules`：按冷却和情绪保护规则拦截

最简单的执行原则是：

1. 先判断是否有高优先级阻塞弹窗
2. 再判断当前场景是否允许激励广告
3. 最后才判断插屏是否可以出
